# Full-game store and LZX comparison

The version 6 Maximum Space store retained 59.70% of four game installs. A
verified WOF/LZX proxy retained 65.51% on the same files. Flummox used
105,177,088 fewer allocated bytes across these games.

| Game | Logical bytes | Flummox at 4 KiB | LZX proxy at 4 KiB | Flummox advantage |
| --- | ---: | ---: | ---: | ---: |
| Balatro | 66,662,933 | 59,772,928 | 60,219,392 | 446,464 |
| Bridge Constructor Portal | 246,114,518 | 99,164,160 | 106,717,184 | 7,553,024 |
| Half-Life | 667,402,434 | 293,928,960 | 327,430,144 | 33,501,184 |
| Terraria | 831,366,992 | 628,690,944 | 692,367,360 | 63,676,416 |
| **Total** | **1,811,546,877** | **1,081,556,992** | **1,186,734,080** | **105,177,088** |

Each command built and verified the complete store, then tested random reads and
ran the round-trip-verified 32 KiB wimlib LZX:50 helper. The LZX proxy keeps a
file raw when that uses less allocated space. Store totals include payload,
header, and index. All four file counts, logical sizes, LZX totals, and
SHA-256 corpus fingerprints match the [earlier version 2 run](2026-09-18-lzx.md).
The [raw results](2026-09-24-lzx.json) contain those controls and per-run sizes.

The version 2 stores occupied 1,131,470,848 bytes on these corpora. Version 6
uses 49,913,856 fewer bytes. Since both the level search and small-file packing
changed, this difference cannot be assigned to one feature. The runs overlapped,
so their timings are not a speed comparison. The helper used wimlib 1.14.5;
the earlier proxy totals reproduced exactly. A direct Game Compressor claim
still needs the [Windows `compact.exe` measurement](2026-09-18-lzx.md#reproduction).
