# Security audit, 2026-10-08

Four read-only reviews of the 0.0.2 source, each by reading code. Nothing was
executed during the reviews, so Windows and Mac findings are reasoned from the
source. Each fix below was made afterwards and passes `just ci`; the Windows
cross-build passes too.

The reviews covered the coordinator and its IPC, direct filesystem operations
and `unsafe` code, the Maximum Space store and mount, and parsers plus the
build and release chain.

## Fixed

| Finding | Change |
|---|---|
| Reclaim deleted the retained original without rechecking the store. An interrupted reclaim finished the deletion at the next start even when the store was unreadable. | Reclaim verifies every chunk first. Recovery opens the store before it finishes a reclaim, and keeps the original when that fails. |
| Rollback after a compaction, with the original still retained, restored the original plus the new empty update layer. Updates the compacted store had absorbed were missing. | Compaction is refused while the original is retained. Rollback uses the retained original only when no compaction is recorded. A lifecycle test covers an update made only before compaction. |
| A Steam manifest's `installdir` could name a folder outside its library with `..` or an absolute path. | The value must be made of ordinary path components. |
| `flummox watch enable` wrote the executable path into `ExecStart=` unquoted. A space split the command, and `%`, `$` or a newline changed the unit. It also overwrote a unit it had not written. | The path is quoted and escaped, control characters are refused, and a foreign unit is left alone. |
| A client sending one byte at a time held the coordinator's only loop: no pause when a game started, no cancel, no progress. | A request must arrive within two seconds. |
| A file swapped for a FIFO after the walk blocked the job's open, and cancel could not interrupt it. | Anchored opens are non-blocking. |
| Direct `PackActivate` skipped the folder refusals other job targets get. | It calls `validate_folder`. |
| `flummox compress --force` and `decompress --force` skipped the same refusals. | Both call `validate_folder`. |
| The watch service selected a finished download by bare number, which could match another launcher's game by title. | It selects by `steam:<appid>`. |
| A selector matched ids and title substrings alike, and an empty selector matched every game. | An id beats a title, a whole title beats part of one, and an empty selector is refused. |
| `state.sqlite`, which lists every game path, could be created in a world-readable folder. | The folder is created owner-only. |
| A relative `XDG_STATE_HOME` was honoured for the library list. | It is ignored, as the specification says. |
| One mount point that was not UTF-8 made every filesystem probe fail. | The mount table is decoded lossily. |
| Size totals could overflow on sparse files with absurd lengths. | The sums saturate. |
| The sandbox status line said the process could only reach the game folder. | It says what is writable. |
| Two `SAFETY` comments claimed alignment and a filesystem type the code does not rely on. | They state what the calls need. |

## Open

Ordered by how much they matter.

1. **Release signing is not restricted to tags.** The `sign` job in
   `.github/workflows/release.yml` runs on a manual dispatch from any branch,
   and the signing key has no password. Anyone who can push a branch can edit
   the workflow and read the signing, AUR and Homebrew secrets. Put `sign` and
   `channels` in a protected environment with a required reviewer and restrict
   them to `v*` tags. This needs repository settings as well as a workflow edit.
2. **Actions are pinned by tag.** `Swatinem/rust-cache` and
   `taiki-e/install-action` run in the job that builds the signed binaries.
   Pin every action to a commit, and drop the cache from release builds.
3. **The worker sandbox includes the coordinator's state.** A worker can reach
   `control.sock` and `queue.sqlite`. A compromised worker could rewrite a
   Maximum Space record so that the next start deletes or moves another
   folder. Give the worker its inputs over stdin and take the state folder out
   of its rules, and validate install records when they are loaded.
4. **`apply_to` follows symlinks in its destination.** A game that swaps a
   directory for a relative symlink through the mount can make a later
   rollback write and delete outside the game folder. Walk the destination
   with anchored opens.
5. **Restore applies setuid bits and ACLs from the store index.** A store from
   someone else can produce a setuid file owned by the person restoring it.
   Strip `0o7000` and `system.*` or `security.*` attributes unless asked.
6. **Folder validation is a list of refusals.** Heroic and Lutris install
   paths are accepted when merely absolute, and `~/Documents` passes. Require
   a path under a discovered or registered library.
7. **Windows.** The pipe name can be taken first by another user and the
   client does not check who the server is. Enqueue has no folder policy, so
   `C:\Windows` is accepted. Files are opened by path with no reparse-point
   check. Decompress may stop at the first file that was never compressed
   (error 342); that one needs a run on Windows to confirm.
8. **Mac.** A file opened for writing during a pass can lose that write: the
   original is deleted after verification with no second identity check.
9. **Store pool path.** `pool.json` inside a store names the pool folder,
   which compaction then chmods and prune deletes from. Accept only the
   configured pool.
10. **Update layer.** Recreating a renamed base directory shows its old
    children again, and a removal reaches the trash before its whiteout is on
    disk.
11. **Path-based opens outside the anchor.** The estimator, the FIEMAP probe
    and the allocation measurement open by path. Nothing is written, but sizes
    of a swapped-in file can be read.
12. **A huge sparse file** makes the range rewrite issue one ioctl per 16 MiB
    of length. Walk mapped ranges instead.
13. **Verification instructions are same-origin.** `docs/install.md` compares
    against the digest shown beside the download, and the Minisign key is also
    printed in the release notes. Lead with Minisign and the key in this
    repository.
14. **Smaller items:** corrupt rows in the queue stop the coordinator from
    starting; library and exclusion lists have no cap; reports for manually
    added games carry the folder path as their key; manifest titles reach the
    terminal with control characters intact; Inno Setup and the Arch image are
    unpinned in the release workflow; `ci.yml` has no `permissions` block.

## Found sound

- The Unix socket sits in an owner-only folder that is created with that mode
  before the bind, and a second coordinator exits.
- Every SQL statement uses bound parameters.
- The btrfs ioctl numbers, struct layouts and the FIEMAP read loop match the
  kernel's, with no out-of-bounds or uninitialised read.
- The store index parser bounds every length, offset and count, and decoded
  chunks are checked for length and BLAKE3 on each uncached read.
- Store paths cannot leave their destination on restore.
- The mount uses `nosuid`, `nodev` and `default_permissions`, with no
  `allow_other`.
- Artwork decoding is limited to PNG and JPEG with size and dimension caps.
- Every dependency comes from crates.io with a checksum.
- The Windows installer is per user and installs no elevated component.
