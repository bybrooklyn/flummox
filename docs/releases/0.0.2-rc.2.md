# Flummox 0.0.2-rc.2

A release candidate. It is here so the new version can be tried on real games
before 0.0.2 is tagged. The four real-game acceptance runs that 0.0.2 requires
(Linux native, Proton, Windows and Mac) have not been recorded yet, so treat
compatibility with any particular game as untested. Arch and Homebrew packages
stay on 0.0.1 until the final release.

Try it on a copy of a game first. Maximum Space moves the original aside and
mounts a store at the game's path; keep the original until you have played the
game from the store.

## Changes since 0.0.2-rc.1

- Estimates cover the whole game. rc.1 totalled only the files it sampled: on
  a 4 GB game it predicted 438 MB for a pass that freed about 1.5 GB.
- Building a Maximum Space store uses every processor core. The same 4 GB
  game went from 26 minutes to about 4, with a byte-identical store.
- A job's worker can no longer open sockets, so it cannot reach the
  background worker's control socket.
- Reclaim and prune check what a Maximum Space record points at before they
  delete it, and stores refuse setuid files.
- In a Maximum Space game, a write that failed partway now counts as a change
  when updates are being compacted.
- A job you paused before it started is still paused after the background
  worker restarts.
- Windows: the background worker no longer crashes when it starts within a
  minute of boot, and Restore no longer stops at a file that was never
  compressed. Neither fix has been run on Windows.

rc.1 was run through the native and Maximum Space cycles on a copy of a real
Linux game, with every file's hash checked at each stage. The
[record](https://github.com/bybrooklyn/flummox/blob/main/docs/validation/2026-10-08-rc1-linux-storage.md)
has the numbers. The game was not launched.

## What is new since 0.0.1

- Overview, Games and one Settings page, with jobs grouped as Running, Waiting,
  Needs attention and History.
- Windows: Steam, Epic, GOG and Heroic discovery, a background worker with a
  tray icon, and opt-in maintenance for each location.
- Mac: native APFS compression and restoration. 0.0.1 was an informational app.
- Storage plans for each drive before a job starts, and a Recovery section for
  interrupted jobs and retained copies.
- Compatibility reports from the app, which measure allocated bytes themselves.
- Custom game folders, as one game or a collection.
- A signed manifest covering every download.

## Upgrading from 0.0.1

Open the new version and it replaces the older background worker by itself,
provided no job is running and no Maximum Space game is mounted. Queue history,
locations, exclusions and reports carry over.

## Safety fixes

A source audit before this candidate found and fixed these, among smaller items
in the [audit record](https://github.com/bybrooklyn/flummox/blob/main/docs/security/2026-10-08-audit.md),
which also lists what is still open:

- Reclaiming the original copy of a Maximum Space game verifies the whole store
  first. 0.0.1 deleted the original without rechecking it.
- Restoring after compacting updates could leave out the updates the compacted
  store had absorbed. Compaction now waits until the original is reclaimed.
- Restoring never writes through a link inside the game folder.
- A job's sandbox no longer reaches the background worker's own files.
- A Steam manifest cannot point a game at a folder outside its library.

## Known limits

- Windows and Mac behaviour has been built and tested by CI only. Neither has
  had an interactive run by a person for this candidate.
- Savings depend on the game. Large recent games that ship their data already
  compressed gain little or nothing.
- On btrfs, saved space is reported as an estimate. Reading the real figure
  needs privileges Flummox does not ask for.
- The Windows installer and the Mac app are not signed by a publisher, so the
  operating system will warn before running them.

## Downloads

Linux: the archive matching your processor, which needs glibc 2.39 or newer.
Mac: the Apple Silicon app ZIP. Windows: the x64 installer or the portable ZIP.
