# Flummox 0.0.2-rc.4

A release candidate. The four real-game acceptance runs that 0.0.2 requires
(Linux native, Proton, Windows and Mac) have not been recorded yet, so treat
compatibility with any particular game as untested. Arch and Homebrew packages
stay on 0.0.1 until the final release.

Try it on a copy of a game first. Maximum Space moves the original aside and
mounts a store at the game's path; keep the original until you have played the
game from the store.

## Changes since 0.0.2-rc.3

This candidate is the result of a full source audit, followed by a second
round. The reports are in
[docs/audit](https://github.com/bybrooklyn/flummox/tree/main/docs/audit) and
[docs/security](https://github.com/bybrooklyn/flummox/tree/main/docs/security),
and list what is still open.

Data safety:

- Recovery after a crash or a job that fails midway keeps unfinished
  transactions recoverable, hashes before swapping a file back, and recovers
  journals whose work directory is gone.
- Compaction stays off a game that is running. Inodes, open files and renames
  stay correct in the mounted view.
- A restart unmounts idle stores and refuses only while a game is running.
  Mounts survive a storage job that fails validation.
- The worker's sandbox is tighter, including the x32 socket syscalls. The
  worker refuses a pipe owned by another account.
- Protected system folders, folders that hold other games, and relative paths
  are refused by the coordinator and by Windows jobs.
- On Mac, files are staged outside signed bundles, each bundle is verified once
  per pass, and a pass continues past files that fail and sweeps orphans.

Accuracy:

- A game counts as played only when code runs from its folder. A starting child
  process no longer looks like a user of the game.
- Savings are judged against the whole install. Sparse and no-copy-on-write
  files are priced by what is on disk. The Freed figure is cross-checked against
  the compressed file size.
- Analysis samples are spread across each file without overlap or gaps.
- A btrfs volume is identified by its filesystem UUID and cross-checked with
  the statfs magic.
- Compatibility reports keep paths out, and old custom-folder reports are
  migrated when they load.

The window and the command line:

- Failed files and worker notes show in the window and in running job progress.
- Games that cannot be compressed offer artwork choices. Unsupported targets
  have a titled page. The tray icon is a Flummox mark.
- A batch of games is queued in one worker request. `flummox doctor --json`
  lists each check.
- A discovery scan that runs past two minutes is abandoned instead of waiting
  forever. A game that the first healthy scan no longer lists is forgotten.
- The Windows and Mac windows use the same wording as the Linux one. Modes,
  stores, jobs and counts use one vocabulary throughout the app and the docs.

Dependencies:

- The lockfile is updated, which clears the `zstd` decompression, `xattr` and
  wasm allocator advisories, and `rusqlite` is 0.43 for a bundled SQLite fix
  (RUSTSEC-2026-0459). Three unmaintained `zbus` crates remain, reached through
  iced, with no patched release.

Release process:

- Acceptance reports are tied to the commit being released, and every stable
  tag needs its own validation record. Release inputs are pinned and the
  licence notices ship with every download, including the Windows installer.

## Known limits

- Windows and Mac behaviour has been built and tested by CI only. Neither has
  had an interactive run by a person for this candidate.
- Savings depend on the game. Large recent games that ship their data already
  compressed gain little or nothing.
- On btrfs, saved space is reported as an estimate. Reading the real figure
  needs privileges Flummox does not ask for.
- The Windows installer and the Mac app are not signed by a publisher, so the
  operating system will warn before running them.

## Downloads

Linux: the archive matching your processor, which needs glibc 2.39 or newer.
Mac: the Apple Silicon app ZIP. Windows: the x64 installer or the portable ZIP.
